# astrbot_plugin_llm_result_final_only · 只发最终回复

AstrBot 原生插件，为内置工具循环 Agent 提供“只发送最终回复”开关。

开启后，中间轮次的普通文本、流式片段、独立思考片段以及 Agent 工具状态均丢弃，不跨步骤缓存、不拼接。Agent 完成后只投递最终响应，保留最终文本、图片等消息组件。工具明确面向用户的直接结果原样放行。模型所需的上下文和工具执行继续保留。

## 安装与开关

1. 在 AstrBot WebUI 的插件页面，选择通过仓库地址安装，填写 `https://github.com/WsureDev/astrbot_plugin_llm_result_final_only`；也可以上传本插件 ZIP 文件，或将本目录放到 `AstrBot/data/plugins/astrbot_plugin_llm_result_final_only/`。
2. 重载插件，打开插件配置。
3. “只发送最终回复”默认开启；关闭并保存后，新请求恢复 AstrBot 原来的输出行为。

没有额外运行依赖，无需修改 AstrBot 配置文件或源码。支持 AstrBot `>=4.28,<4.30`，仅作用于内置工具循环 Agent；其他 Agent 类型不会被拦截。版本范围有意限制在已核查的内核系列，升级到新系列时需要重新验证。

AstrBot 的会话插件白名单照常生效：本插件未参与该请求时，输出保持原样。不同请求不共享消息缓存；子 Agent 复用同一事件但使用不同请求对象时，也不会误命中主 Agent 的标记。

## 流式与合并设置

无需为了此插件关闭 AstrBot 的流式设置。流式情况下，中间片段同样会被丢弃，最终回答生成完毕后通过原流式通道一次投递，因而不再有逐字显示效果。

如果启用了 AstrBot 自带的“合并 Agent 中间消息”，发送链路也只会收到最后一轮文本，没有中间文本可以合并。插件自身不缓存各轮内容。

平台或其他插件仍可能把最终回答拆成多条物理消息。若还要求聊天平台只出现一条消息，请关闭 AstrBot 和相关插件的分段回复设置。

## 实现与边界

当前 AstrBot 缺少可在所有中间文本发送前调用的官方响应钩子。因此本插件用标准 `Star`、`on_llm_request`、`initialize`、`terminate` 管理生命周期，并在运行时包装 `ToolLoopAgentRunner.step()`：

- 官方请求钩子标记本次请求，遵守 AstrBot 的插件启用范围。
- 包装器丢弃该请求的中间 `llm_result`、`streaming_delta` 及工具状态，`tool_direct_result` 这类明确面向用户的工具消息原样放行。
- 当前步骤正常结束且 Agent 完成后，从 `get_final_llm_resp()` 读取最终响应，只投递一次。
- 如果工具直接正常结束当前轮次，框架没有正式最终响应，则保留这一个终止步骤的最后一条正文，不取更早步骤的内容。主 Agent 的“已经指派了任务”和后台稍后的结果分别发送，不等后台完成，不合并为一条。
- 保留错误、中止控制事件和用量统计。中止、异常或没有最终内容时，不拿先前的中间文本补发。
- 插件停用或重载时恢复原方法；如果其他插件后来也包装了该方法，不覆盖对方的包装，旧包装停用后直接透传。

它是对内核方法的运行时包装，并非仅靠官方响应钩子实现。没有修改磁盘上的 AstrBot 源码；同样包装此方法的插件仍需一起验证兼容性。配置开关在请求开始时确定，已开始的步骤会按开始时的状态处理。

这个开关阻断的是 **Agent 中间自动输出**。`send_message_to_user`、工具内部的 `event.send()`、插件自行发送，以及 Live Mode 的自定义处理并不保证完全静默。`tool_direct_result` 表示工具明确发送给用户的结果，会原样保留，其中的图片、文件和图文消息不会被当成工具状态丢弃。

插件不会根据文字内容猜测哪些句子属于分析。如果模型把分析写进最后一轮普通正文，需要另外约束模型的最终回答格式，或者结合思考标签清理插件。

## 开发验证

插件源码是 Python，以符合 AstrBot 插件协议。独立实验和回归脚本放在 `~/experiments/astrbot-final-only-plugin/`，不随安装包发布。

在 v4.28.0、v4.29.4 和核查时的 master 上各通过 25 项源码回归（合计 75 项），并通过 Ruff 检查。回归执行上游真实的 `step()`、`run_agent()`、消息链及响应类型，用模拟模型与工具输入覆盖流式回退、重查询、错误、中止、并发和重载，以及工具直接结束时保留当前步骤收尾、不复用更早步骤或推理、工具图文原样发送。与 GSVI 插件联合回归覆盖两种加载顺序及主 Agent 先确认、后台稍后回传。ZIP 另通过上游实际元数据校验和解压流程。尚未连接真实模型或聊天平台实测。

市场核查发现的“不要想啥说啥啊～”（`youshen2/astrbot_plugin_thinking_filter`）只清理思考标签和独立推理字段；“最终文本润色”（`cyilin36/astrbot_plugin_chat_polisher`）在发送前润色文本。所核查源码均没有实现工具调用轮次的中间普通文本阻断，因此新建此插件。
